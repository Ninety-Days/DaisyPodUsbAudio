# Drift correction and interpolation

How the transport absorbs the host/device clock difference without ever
emitting a discontinuity, what the interpolator costs, and how good it actually
is.

The README gives the headline figures. This file gives the measurements and the
reasoning behind them.

---

## The ring architecture

Two SPSC rings sit between the USB ISR and the SAI DMA callback. These sizes
were fixed early and never revisited:

| | | |
|---|---|---|
| `pb_ring` | playback (host → DAC) | 512 frames = 10.67 ms @ 48 kHz |
| `rec_ring` | record (ADC → host) | 512 frames |
| `PB_TARGET` / `REC_TARGET` | steady-state fill | 256 frames = 5.33 ms |
| `SAMPLES_NOM` | frames per USB packet | 48 |

## The approach

Both rings are read at a fractional position advancing by nominally exactly one
frame, tilted a few tens of ppm by a proportional loop on the fill level. The
packet is therefore always exactly nominal length — the Adaptive endpoint
descriptor tells the truth — and the clock difference is absorbed by
interpolation rather than by adding or dropping a frame. No discontinuity is
ever emitted.

The interpolator is a **polyphase windowed-sinc fractional-delay filter**: 32
taps per phase, 128 phase rows plus a guard row, with linear blending between
adjacent rows. The table is 16 KB of `const float32` in `fd_sinc_table.h`,
generated by `gen_table.py`.

## Why a table is worth it

The read phase does not sit still. It sweeps 0→1 continuously, so whatever the
interpolator does to high frequencies arrives as slow **amplitude modulation**,
not as a static roll-off. The modulation rate is set by the corrector's rate
tilt:

    AM rate = |tilt| × 48000 / 65536 = |tilt| × 0.7324 Hz

`tilt` is an integer, reported live by `read_transport_diagnostics.py`. On the
development board it sits near 3–4 and wanders roughly 2–8 across the
corrector's own sawtooth: at the residual crystal offset a whole sample of
drift accumulates about every 17 seconds, and the reader crossing that
boundary shows as a step in ring fill. Tilt therefore sweeps the AM rate
between roughly 1.5 and 6 Hz, through the ~4 Hz peak of human sensitivity to
slow amplitude modulation, once per cycle. That sweep, not the depth alone, is
the argument for the table.

Note which way this cuts. A board with a larger standing clock offset carries
proportionally more tilt and a proportionally faster AM rate: measured against
stock libDaisy dividers, tilt runs 13–19 and the AM rate 9.5–13.9 Hz, *further*
from the 4 Hz sensitivity peak than the patched board's 1.5–5.9 Hz, not closer.
The worst case for AM audibility is a board whose offset is small, which is to
say a correctly clocked one. That is why the table is justified by this argument
and the PLL3 patch is not; the patch is justified by ring headroom instead, and
[`CLOCKING.md`](CLOCKING.md) §2 makes that case with the same two runs. With the
shipped polyphase table the depth is 0.0002 dB either way, so neither rate is
audible — the argument decides which interpolator to ship, not which clock.

## Measured: interpolation error

Worst-case output error against an ideal fractional delay:

| | linear | Catmull-Rom | polyphase sinc |
|---|---|---|---|
| 1 kHz | −53.4 dB | −88.8 dB | **−101.2 dB** |
| 5 kHz | −25.5 dB | −45.9 dB | **−99.8 dB** |
| 10 kHz | −13.7 dB | −24.5 dB | **−97.2 dB** |
| 15 kHz | −7.0 dB | −12.0 dB | **−88.0 dB** |
| 20 kHz | −2.6 dB | −4.4 dB | **−37.5 dB** |

Relative to the tone, as the worst case of `|H(ω,d) − e^(−jωd)|` over the full
fractional-delay range. Three independent routes agree to 0.2 dB: the closed
form above, `gen_table.py`'s remeasurement on the float32 coefficients, and
`tests/interp/check.sh` driving the shipped reader. An earlier version of this
table was up to 4.6 dB optimistic because `interp_check.c` held the signal
phase at zero, which measures one projection of a complex error instead of its
magnitude; it now sweeps phase.

## Measured: AM depth

The thing you actually hear, measured by driving the shipped reader directly
(`tests/am_probe/`):

| tone | linear | Catmull-Rom | polyphase sinc |
|---|---|---|---|
| 12 kHz | 3.01 dB | 1.07 dB | **0.0002 dB** |
| 15 kHz | 5.11 dB | 2.53 dB | **0.0003 dB** |
| 18 kHz | 8.34 dB | 5.26 dB | **0.0005 dB** |
| 20 kHz | 11.74 dB | 8.41 dB | **0.0023 dB** |

The sinc column is a closed-form upper bound (`tests/am_probe/closed_form.py`,
computed from the shipped coefficient table); direct simulation measures lower
still — 0.00002 dB at 12 kHz. Below about 0.001 dB the two methods disagree by
3–9× because both are near the floor of what float32 output and a 24-bit
clamp resolve, so treat these as "not measurable" rather than as values. The
linear and Catmull-Rom columns are exact and reproduce by both methods.

## Two things that are not optional

**The row blend.** Snapping to the nearest of 128 phase rows, without blending,
measures −59.8 dBFS at 1 kHz — worse than Catmull-Rom. A stepped delay
reintroduces exactly the discontinuity this corrector exists to remove, just
60 dB quieter. If the table needs to shrink, shrink the row count and keep the
blend.

**The 24-bit clamp.** Both interpolation paths clamp; that clamp is
load-bearing, not decorative. On material already hard-clipped at full scale a
cubic overshoots by up to 1.02 dB and the sinc by up to 1.25 dB.

## The top of the band is a theoretical limit, not a shortfall

An ideal fractional delay at Nyquist is e^(−jπd), which at d = 0.5 is purely
imaginary, while any real FIR has a purely real response at ω = π. So |H| there
is necessarily zero, at any tap count. The 20 kHz figure is that limit.

Separately, row 0 is not a delta but a lowpass cornered at 0.97 × Nyquist,
which puts a fixed −0.12 dB at 20 kHz on every sample regardless of phase — a
static tilt at the very top, not modulation, and the price of the flatness
below it.

## Cost

The coefficients depend only on the phase, so the row blend runs once per frame
and is reused across channels — 32 blends plus 32 MACs per channel. The row
index advances by at most 1/2048 per sample at full tilt authority, so the same
two rows serve 16+ consecutive samples and the table stays hot in cache. Ring
headroom needed is idx−15 through idx+16, against a TARGET fill of 256 frames
in a 512-frame ring.

Rebuild with `-DFD_USE_SINC=0` to fall back to Catmull-Rom (4 taps, no table)
and A/B the two on hardware.

## Two figures that are easy to confuse

Kept separate deliberately:

- *Interpolation error* — how far the output is from an ideal fractional delay.
  The tables above. This is what limits quality.
- *Arithmetic error* — float32 rounding inside the kernel, a few LSB of a
  24-bit sample. This says nothing about transparency and must not be quoted as
  if it did.

`tests/interp/check.sh` reproduces every number in the first table;
`tests/am_probe/` reproduces the second.
